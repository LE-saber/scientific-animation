# 制片工程、交付与检验标准

## 0. 产物优先级

必须产出**实际可播放动画**，而不是只交分镜表、口播稿、文字方案、待完成代码或生成提示词。推荐交付：

1. `final.mp4`（成片，按用户要求含可见解说字幕；可选对应旁白音轨）；
2. `preview.html`（可交互、可拖动进度的离线播放/演示，可选，但有助于评估）；
3. `source.zip`（源码、必要素材、字幕 SRT、数据与运行说明，若需求包含可编辑成果）；
4. `qa_report.json` 或精简核验报告，记录规格、源假设、数据核验及未实现功能。

仅仅将源代码放在 ZIP 而无已可视化动画，不是完成交付。对于不要求附加文件的用户可只交成片。

## 1. 输入整理

- 确认需要读取的 PDF/文档/HTML/ZIP/代码及用户提供的参考画面。对图片型 PDF 渲染页面直接看，不在内容无法读取时自行猜公式。
- 记录用户**最后确定的设定**，它覆盖旧版本冲突的设定；区分新需求、旧动画问题、真实工程参数、为讲解而作的假设。
- 给每个数值/路线/动画事件绑定唯一来源或计算生成过程；外部数值如需最新验证再查可靠来源。

## 2. 技术路径（按可用工具选最快可靠组合）

- **代码优先的确定性路径**：Motion Canvas、Manim、Remotion、HTML Canvas/SVG、Python + FFmpeg。选能在当前环境真正运行并导出的视频工具，不要假设已安装。
- 用于机械空间关系的有限 2.5D 可以使用简单的正交/轴测投影，不需要完整写实三维。
- 精确算法轨迹、图形、标签和数值要由代码渲染。视频模型只在已授权且有把握时辅助非关键质感，不可让生成模型任意编造公式或坐标。
- **最小可运行工程先行**：建立项目目录、主 render 函数、分镜时间轴、一个真实场景、字幕样例、视频输出命令。先渲染 2–3 秒短样片并检查，再完整渲染。
- 对于渲染昂贵的项目，可按镜头/时间分段、并行渲染，然后无损/少损拼接，校正音画同步；检查后再写最终文件。
- 配音按实际工具可用性生成；不能生成声音时仍应提供带**可见字幕**的动画，并在最终交付中清楚注明音频缺失。不得凭空声称已配音。
- 不在包内分发专有字体；使用有许可的本地字体或者合法替代，并在源工程说明。

## 3. 验证关卡

### 视觉检查

- 渲染代表帧：开场、每个主要概念画面、关键动作、公式/矩阵、交接、片尾、字幕最长一句；查看有没有遮挡、裁切、细字、闪动、字体缺字。
- 至少检查关键动作首/中/尾的连续性。不能仅凭代码编译成功就判“动画质量完成”。
- 用户纠正过的场景空间/货物流转须专门核验，如架下穿行、货物来自缓存、归还位合法。

### 算法与数据核验

- 可计算的数据使用原研究代码或独立计算复核；对路线、最优成本、时间线、总任务数和同口径对比记录检查结果。
- 标清“实验给出的值”“从材料计算的值”“简化演示虚构数据”。任何对比结论必须与实际计算一致。

### 媒体技术检查（包内脚本）

```bash
python scripts/qa_media.py path/to/final.mp4 --duration 60 --fps 60 --width 1920 --height 1080 --require-audio --out path/to/qa
```

脚本基于 FFmpeg/ffprobe：检测流、规格、时长、编码、文件 SHA-256、最终成片完整解码，并尽可能创建关键帧预览。`--require-audio` 仅在用户明确要求且实际应有音轨时使用。不允许忽略工具返回的错误码。生成后再次验证 **最终交付文件**，不只验证临时片段。

### 打包与交付检查

- 归档之后，打开 ZIP 并检查 CRC、关键文件存在、可编辑源码、字幕、媒体/材料清单、字体许可证限制。
- 检查要分享的文件真实存在，路径可以访问，文件不是零字节，hash 与核验报告一致；链接必须是实际生成的路径。
- 首先提供可直接观看的视频链接，其次给离线交互版和源包；简短说明本版做到了什么、还没做到什么。

## 4. 异常处理和降级

- 如果 MP4 生成失败：先修复实际错误并再次渲染；工具/依赖真的缺失时，用同样源数据导出**单文件可播放的 HTML Canvas 动画**或 GIF（必须真的能动，不得只有静态截图），同时尽量补上字幕、播放进度与控制。
- 若仅缺少 TTS/配音，视频应继续输出可见解说字幕，明确说明没有旁白音轨。
- 若原数据缺口涉及结果正确性，改用有注明的**示意案例**，不制造“实验已证实”结果。
- 绝不以“已完成”描述未写出、未检查的文件；无法达成格式要求时如实说明实际可交付替代，不编造路径或未来完成时间。
