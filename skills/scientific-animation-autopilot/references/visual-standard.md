# 科研算法动画视觉与内容规范

本标准源自用户此前给出的《科研算法可视化动画创作需求》以及后续针对货运机器人动画的修正。用于科研、算法、工程场景、竞赛答辩和科普解释；不要把具体 RMFS 场景默认套用到其他项目。

## A. 风格：以视觉讲数学，而非 PPT 或 AI 风格 HUD

- 定位：**Minimalist 2D Vector Motion Graphics / Scientific Explainer / Diagrammatic Animation / Scene-integrated Mathematical Visualization**。以 2D 正交视角为主，只有解释机械空间关系时使用少量 2.5D；不需要写实工业模型。
- 画面主体是可识别的工程场景与数据关系。抽象图形（网格、方块、路线、箭头、线段、矩阵）必须承载含义；不要为装饰而放光柱、数据流、发光边框、全息面板或过多 UI 控件。
- **默认浅色方案**：背景 #F5F5F3、主要表面 #FFFFFF、网格/设备 #D6D6D3、正文 #222222、辅助信息 #656565；唯一主强调色可选暖橙 #C75A32。确有多种状态必须区分时，再增加有确定语义的第二颜色。用户指定黑白等其他配色时遵从用户；**避免默认蓝黑、紫黑、青紫霓虹的“AI 味”**。
- 控制视觉密度：让当前操作对象最清晰，次要对象淡化；不同层次位置、线宽、字号稳定。少量有目的的停顿，高亮后保持足够阅读时间。
- 设计流动的逻辑镜头：同一场景内推拉、平移、形变（morph）、路径飞入矩阵、矩阵回归路径、时间轴展开，尽量少用硬切和独立 PPT 页；运动缓动必须服务概念。
- 表达形式可借鉴 3Blue1Brown、Alan Becker 关于“几何先于代数”的思想，但不要复制角色、画面或非授权素材。所有复杂数字/路线由可靠数据生成，而非由视频模型“猜”。

## B. 字幕与字体

- **不要把“去掉小字”误解为“取消字幕”**。解说字幕默认可见，中文首选**微软雅黑 Bold（Microsoft YaHei Bold）**，1080p 约 42–54px；一般 1 行，必要时最多 2 行；位于底部安全区，保持足够对比与停留时间。
- 设备、章节、局部标题可使用**华文中宋（STZhongsong）**，正文、数字、数学符号使用更易读的无衬线；保持字号差异明确，不能全部挤成细小脚注。
- 不要增加持续显示的小号旁白复述、英文口号、AI 常见“Section 01 / Simulation Active / DATA-DRIVEN”等装饰性标签。公式/任务编号只在解释相关概念时出现。
- 两个中文字体均可能是专有字体：仅在宿主环境已授权并真实可用时使用；不得把 Microsoft YaHei 或华文中宋的字体文件随成片源码包/Skill 分发。缺少字库时选择适当合法字体（如 Noto Sans CJK / Noto Serif CJK），并如实说明，**不得虚报字体已使用**。
- 每句配音与字幕对应，字体实际在最终输出中可视检查；对于音频失效的媒体播放器，字幕仍足够解释主要概念。

## C. 科学与动画一致性

1. 从研究材料提取实体（机器人、任务、货物、站、缓存）、状态、约束、算法、变量、实验数据，并形成 **事实台账**：来源/假设/演示化处理/待验证。
2. 固定单位、坐标系、时间基准与比例：数据里“模型时间单位”不可直接声称“秒”；不同实验的参数、障碍/可通行设置不能混用。
3. **场景融合数学**：A* 路径直接在可通行地面上显现；成本矩阵从实际候选关系生成；最优配对回到对应机器人；离散事件在时间轴与机器人动作同时更新；公式里的每个量都有可见的物理指向。
4. 先产生确定性计算（脚本/原代码/校验数据），再制作路径和数值动效。绝不可先拍漂亮镜头再反向编造数值。无可验证数字时改为符号或明确标注“示意”。
5. 视频比较公平：相同任务流、初始状态、环境和约束；列出各方案真正不同的决策规则。只说本轮实验事实，不把单轮匹配最优误称长期全局最优。
6. 对完整任务须展示关键起止：来源→处理/计算→动作→结果。任务持续时间、位置、状态和载货关系应连续；货物不可凭空生成或消失。
7. 不把尚未开发的功能包装成已实现：例如多机器人避碰、全局时空最优、速度曲线、缓存容量控制、真实飞梯联动，应与现有代码明确区分。

## D. 内容节奏与画幅

- 默认 16:9，1920×1080，30 或 60 fps（设备允许优先 60）；如用户指定其他比例/时长，以其为准。
- 讲解结构建议为“问题 → 物理场景 → 单步算法 → 多对象协作 → 真实执行与事件 → 结果/局限”；这只是参考，不能机械地把所有片子切成六段。
- 短片的每个画面只讲一个可理解的结论；配音用自然、直接的简中句子，避免套话（“接下来让我们一起见证…”、“赋能革新…”）。
- 背景留白不是“没内容”：要留给路径运动、数据演变和主体观察；公式、字幕与对象应避免碰撞。
- 默认配清晰普通话旁白、与其一致的可视字幕，轻微提示音可用，背景配乐不是必需；缺失音源必须透明标注，不能假装有声音。

## E. 视觉检查（逐镜）

- 无小字密集堆叠、无字幕与主体重叠、无缩放导致字形变形、无半截标签/裁剪。
- 映射一致：机器人/任务/路线/矩阵值/时刻按同一份数据，动作不能穿过真实障碍但可以穿过明示可通行投影。
- 关键视觉因果清晰：观众关闭声音后仍能大致说出“发生了什么，算法改变了什么”。
- 用户曾经纠正过的物理设定优先级高于旧文档的同场景早期假设。
