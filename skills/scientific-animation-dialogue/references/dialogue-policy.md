# 交互询问版：最小成本确认策略

## 判定何时提问

最多建议 **1–2 轮关键澄清**（不是固定每轮都要问）。任何问题应能改变科学结论、产品输出或大量返工概率；其余全部采用可逆默认值。

优先级：
1. 科学核心材料冲突：新旧资料哪个约束有效？只有当无法据更新时间/明确性判定时才问。
2. 研究任务边界：作品是解释算法原理、比较算法结果，还是展示真实机械过程？如果现有材料足够清晰就不要问。
3. 交付定义：只有用户明确要求多个不兼容目标（例如视频需有口播却禁止音频）时才问。

不应反复问：时长、16:9、高清、默认简体中文、是否保留字幕、是否要源工程、配色喜好、是否需要“AI 风格”等；默认值见 `references/visual-standard.md`，用户已有明确偏好直接沿用。

## 一条消息最多包含什么

- 一句话指出观察到的**具体分歧**。
- 一个主要决策问题，带 2–3 个简短选项和一个推荐默认值；如果独立细节真的同时必要，最多 3 个简短问题，不使用大表单。
- 可以说明“未回复则按 X 处理”但**不能在尚未回复的同一轮假定用户已同意不可逆选择**；必要时只推进不影响该选择的素材核验/代码框架。

## 两个用户交互关卡

1. **开工前（可选）**：检查实体、场景、算法与用户所述范围后，针对实质冲突问一次；能从材料中确定就直接开始。
2. **样片后（可选）**：可给出一个 3–8 秒真的渲染出来的可播放样片或若干代表帧，要求用户**只确认一个会导致重做的关键问题**（比如飞梯是否固定、料箱归还规则、需要解释哪种算法）；若没有疑问，继续完成不需要再询问。

## 节省 token 的规则

- 用户已上传的材料不要让他再次描述；一次扫描建立事实清单，后面引用，不逐镜重复问。
- 不发长篇分镜和冗余“思考过程”，专业执行决策自行承担。
- 有实物结果后针对问题反馈比抽象选择题有效；尽量避免“要不要我开始？”的形式化许可询问。
- 制作完成后给结果而不是再问是否需要成片。

## 示例

用户：`@科研动画制作·交互确认 依据课件制作算法动画，稍后我会提供参考 HTML`。
正确回应：先读取已附材料与现成 HTML，如果确实尚未上传参考且风格对齐是硬要求，可以问：“你希望以稍后提供的 HTML 为唯一配色依据，还是先按默认白黑灰方案制作？默认先做白黑灰，后续再对齐。”

用户：`参考之前的完整动画，货架可以穿行，归还位置由调度选择`。
正确行为：不再问货架能否穿行或是否必须回原位置；直接修正路径图、货流来源、返程逻辑并出样片。
